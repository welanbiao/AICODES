## 2. 项目现在处于什么阶段

**阶段：可玩的垂直切片 / 垂直商业 Demo（手机尺寸已成型，主循环已通）。**

1. 标题 → 女主人设 → DeepSeek 测通 → 进入游戏

- 脚本场景库（`ZC_SCENES`）写全了，但**第一次选择之后默认走 AI 续写**，后半脚本更多是结局/保底  
- 没有音效、没有语音、没有应用商店包体  
- 图像是现成 CG，不是动态立绘分层  

商业规格（已按这个做，请保持）：

- 画幅按手机 **390 × 844**  
- 角色图只用 AI 图，不用 SVG/3D 拼人

- 视觉不要做成恋综模拟器那套粉白；本作成色是**暗金 + 夜色职场**  
- 卖点是 **「高冷总裁攻略玩家」**：系统在攻略女主，玩家扮演被攻略的基层，可以接、也可以故意添堵

## 4. 玩家怎么玩（从开机到结局）

### 4.1 进入顺序（固定，不要插广告页）

1. **标题**《高冷总裁攻略我》  
2. **你是谁**：姓名、年龄、外形三选一（明亮 / 清冷 / 温柔）、外貌描述、性格  
3. **接入 API**：测通 DeepSeek 才能进游戏  
4. **四步简短教程**（关键词标红）  
   - 公司 100 天后破产，他必须让你好感到 100  
   - 你是基层，**不知道系统**，凭心意行动  
   - 你可以故意**添堵**  
   - 点顶部「介入判定」，只改**上一轮**  

### 4.2 一局在干什么

玩家扮演基层员工（默认名苏晚）。陆晏辞被「嘴毒系统」逼着 100 天内把她的好感刷到 100，否则集团破产。

玩家**看不见系统面板**（只有陆晏辞能看见）。玩家看到的是：一个话少、冷脸、出现位置不对的总裁。所以正确玩法不是「讨好攻略对象」，而是：

- 接住他笨拙的关心  
- 或者故意添堵、躲开、当他有病  
- 公开场合接太明显会积**议论**；盘问跟踪会积**警惕**  

### 4.3 屏幕怎么读

上下两块不透明暗金底板，各约占屏幕 **1/5**，中间是立绘。立绘从顶栏下方开始，**脸不被顶栏挡住**。

**顶栏**

- 菜单 / 玩家名 / **介入判定**  
- 好感 0–100 与条  
- 剩余天数 + **剧情时钟**（不是现实秒表）  
- **任务**条：当前系统任务 + 判定（进行中 / 成功 / 失败），点开看任务清单  

**对话框（与顶栏同高）**

- 左侧名字牌：旁白 / 动作 / 陆晏辞  
- 名字右侧小字：**当前剧情时间**（如 18:47）  
- 正文固定区域，**不能上下滑动**  
- 底下淡灰「冷知识」：游玩提示（点对话框继续、专梯你进不去、即达走钱包等）  

演出顺序：点对话框或立绘推进  

旁白 → 动作 → 陆晏辞台词 →（系统弹窗，仅他可见）→ 三个动作选项 + 自由输入  

### 4.4 怎么推进剧情

- 每轮**必须有三个动作选项**，不够引擎会补。  
- 也可以自己写一句动作（不是写心情）。  
- 选完后：扣剧情分钟 → 改好感/警惕/议论/靠谱 → DeepSeek 生成下一幕。  
- **同一地点不换底图**；只有 `place`（地点名）变了才换 CG。这是「站桩」规则：人可以一直站在电梯/工位，剧情继续说。  

开场例外：`meet1`（电梯）是写死脚本，选完进入 `hint_phone`，强制去看手机档案。档案、身份、集团、总部地图、城市地图都点过之后，教程才算完成，才能真正离开电梯厅。

### 4.5 手机（右下可拖的手机图标）

桌面应用：

| 应用 | 做什么 |
| --- | --- |
| 天气 | 仿 iOS 天气。滨江 / 晏辞总部 / 滨湾可切换。逐时、十日、空气质量、体感等跟**剧情时钟和日历日**走。第 9 的倍数日会下雨并出预警。 |
| 日历 | 本月格子 + 第几天 + 倒计时 |
| 钱包 | 余额 + 流水。即达购物从这里扣。 |
| 即达 | 仿外卖软件（不是淘宝）。分类、搜索、商家、详情、购物车、钱包结算、订单（配送中/已送达）。新人满 20 减 5。送到「裙楼 7F 工位」。 |
| 系统 | 本机误收的系统残页，女主不该看见，只能看到很残的字段 |
| 集团 | 先看宣传册，再「进入公司详细资料」变成带目录的官网（首页/关于/年报/采访/新闻/架构） |
| 档案 | 陆晏辞系统档案（教程关键） |
| 身份 | 玩家自己 |
| 地图 | 总部航拍 / 滨江航拍。图上**没有字**，名字用 HTML 标注。点地点 → 内部子地点「前往」→ 可能撞见陆晏辞，AI 写这一遇 |
| 讯息 | 仿短信。档案通知、未知号码（陆晏辞，话极短，可当微信回）、集团通知、同事陈絮。未知号码在 API 通时按玩家原话回 |

### 4.6 怎么结束

| 结局 | 条件 |
| --- | --- |
| 完美通关 | 好感到 100（倒计时仍在或刚好归零） |
| 力挽狂澜 | 天数用尽，好感 ≥80 但不到 100；系统先给「最后一天」（该场好感 ×1.5），仍没满则保全公司、他卸任 |
| 攻略失败 · 破产 | 天数用尽且好感不够。文案随好感分温/默/冷三档 |
| 攻略失败 · 崩溃 | 好感连续 3 个跨日仍 ≤ -20，他心悸倒下 |

完美通关后可进日谈。

## 5. 我做成了哪些「设计」，而不只是把设定排版

下面这些都不在原始文字设定里，是做成游戏之后加上的。接手时请当成**已定产品规则**，不要无故拆掉。

### 5.1 信息差是核心乐趣

- 系统频道只对陆晏辞说话，嘴毒、催他攻略、骂他像查勤。  
- 玩家作为女主**不知道**有系统。教程必须写明这一点。  
- 所以选项是「女主此刻能做的动作」，不是「帮总裁完成任务」。  

### 5.2 好感是女主心理，不是任务勾选

加减分看女主当下感受：

- 接住他嘴硬的关心 → 涨  
- 盘问、跟踪、当众处刑感 → 扣，并抬**警惕**  
- 工位/会议/餐厅等公开场合 → 积**议论**，同事短信会余波  
- 连续接住关心 → **靠谱**升高，以后同样善意会更好用  

顶部「介入判定」只能改**上一轮**的加减，不能一次拉满。这是给玩家的「我不服判定」出口，不是作弊到满分。

### 5.3 时间是剧情时间

顶栏的时分秒**不是现实倒计时**。内部用 `clockMin`（从 18:47 开场）。每个动作估算分钟（看手机约 6 分钟，短对话 8–15，吃饭约 50，开会约 55，加班约 90）。跨天才扣「剩余天数」。

### 5.4 任务是他的任务，不是玩家任务

任务清单是系统派给陆晏辞的（偶遇、倒水、送伞、请吃饭…）。HUD 上的成功/失败，看女主**有没有真的接住这件事**。口头答应不算。点任务栏打开完整清单。

### 5.5 第一次之后，剧情由模型续写

写死脚本主要用于：

- 开场电梯 + 手机教程  
- 结局节点（通关、最后一天、日谈）  

其余选择会调用 DeepSeek，要求输出下一幕 JSON：旁白、动作、短台词、系统对话、三个动作选项、花费分钟。失败时引擎有本地保底，不会卡死。

陆晏辞台词被锁死在短句风格：顺路 / 随便 / 别多想 / 放着 / 走 / 吃 / 加班？ / ……  
禁止解释、讨好、大段内心。

### 5.6 地图是「去一个地方」，不是菜单传送

航拍图本身不写字（避免裁切错位）。点标注 → 看内部地点 →「前往」。每个内部点有概率刷新陆晏辞，刷新则生成一遇。这是自由行动，不是主线章节列表。

### 5.7 经济是轻的，但是真扣钱

开局钱包约 1284.6。即达下单走钱包，记流水，进背包。订单状态用剧情时钟判断「配送中 / 已送达」。天气下雨时文案会提示配送变慢（氛围，不是另做一套物流模拟）。

## 7. 界面原则（改 UI 前先看）

这些是迭代里反复改过、已经定下来的，不要退回旧方案：

1. **顶栏、对话框都是不透明暗金**，不要半透明奶油粉、不要恋综贴纸风。  
2. **顶栏约占 1/5**，四行：菜单、好感、剩余、任务。不要压成一条玻璃胶囊。  
3. **立绘整体下移**，脸出现在顶栏下方；不要为了露脸去改任务栏结构。  
4. **对话框和顶栏一样高**，台词靠上，底下用淡灰冷知识补白；不要做成窄条贴屏幕底，也不要让正文区域能上下拖。  
5. 旁白/名字右侧显示**剧情时间**。  
6. 集团是白底宣传册 → 官网目录，不要做成游戏内任务板。  
7. 地图是无字航拍 + 外置标注。  
8. 购物应用叫**即达**，走钱包，不要做成淘宝皮。

## 8. 技术上接手需要知道的（产品级）

- 单页 HTML，无构建步骤。改 `js/` `css/` 刷新即可。  
- 密钥：`sessionStorage` 的 `zongcai-deepseek-key`。测通逻辑在 `js/api.js`。  
- 续写、自由输入判定、地图偶遇、未知号码回复，都走同一套 `ZC_API.complete`。没网或失败会回本地规则，游戏仍可点。  
- 自由输入会先分类（敌意 / 盘问 / 亲密 / 离开 / 沉默 / 工作 / 道谢 / 拒绝 / 接受等），再映射到三个选项里最接近的判定。  
- 教程完成标记：`seenLuCard` `seenIdentity` `seenCorp` `seenMapDesk` `seenMapTower`。

## 9. 建议你接手后先做的三件事

1. **自己当玩家走一遍**：标题 → 填人设 → 测 API → 电梯 → 强制看手机五件套 → 选一次动作看 AI 是否续上 → 打开天气/即达/地图各点一次。  
2. **对照你原来的文字设定**：看哪些情节还在脚本里、哪些已经改成「系统任务 + AI 续写」。不要假设每一场茶水间/下雨都还会按原文逐字播放。  
3. **再提需求时按系统说**：例如「好感判定太松」「地图撞见概率」「即达要不要影响剧情」，而不是从零描述成另一个恋爱游戏。  

如果你要加新主线场：优先考虑是写成 `ZC_SCENES` 里的脚本节点，还是只加任务/地点让 AI 在该 place 续。当前引擎更偏向后者。
